LLM Evals FAQ · Husain & Shankar, 2026
🔍 Error analysis first, infra second. Review 20–50 real outputs manually before building any automated eval.
👑 Benevolent dictator. One domain expert as the quality decision maker — nurse, not committee.
✅ Binary pass/fail beats Likert. 1–5 ratings are subjective and inconsistent. Pass/fail forces clarity.
🏥 Clinical = false negatives cost more. Missing something in a medical review is worse than over-flagging.
⚠ Evaluation criteria drift · Shreya Shankar, Stanford
"Users start with a simple rubric — but as they see more examples, they refine it. Standard ML eval assumes fixed criteria. Real evals don't."
The Three Gulfs (EvalGen / DocWrangler)
1 Comprehension — What's actually in my data? You can't write good prompts for data you don't understand.
2 Specification — How do I write the right prompt? Accumulated observations are hard to operationalize.
3 Generalization — Will this work at scale? A prompt that works on 10 examples can fail on 10,000.

Lessons Learned · Personal + Work

What the journey
actually taught me.

1
Start with the problem. Always.
Every tool I regretted was adopted because it was impressive, not because it solved something real.
2
Garbage in, garbage out.
Cleaning data before the LLM beats upgrading the model. Quality input is the real leverage.
3
Evaluation is non-negotiable.
Golden dataset at work. "Does this save time?" personally. Without it, you're flying blind.
4
AI isn't the best tool for every step.
Classical ML, agents, Discord — the best stack is hybrid. Use AI where it wins.
5
Things change fast. That's the point.
OpenClaw → Hermes in months. The tools change; the mindset (start with a problem) doesn't.
